## 三、其余四条修复的核实

### 3.1 自动刷新护栏 —— 实现对，但「退出编辑态那一刻」什么都不会发生

用 ref 而不是把 `readOnly` 写进依赖，**这个判断是对的**：写进依赖的话，退出编辑态会让
effect 重跑，此时 `view.state.doc` 是用户改过的、`value` 是外部那份，两者不等 → 直接
dispatch 覆盖，用户的改动当场消失。新增用例「退出编辑态这一下不许把外部那份旧内容灌回来」
锁的正是这条，有效。

**但要把话说完整：退出编辑态那一刻，没有任何东西去做和解。** 那个 effect 只在 `value`
变化时跑，退出编辑态时 `value` 没变，于是：

- 编辑器里是用户改过的内容；
- store 里的 `document.content` 是外部那份；
- 二者**永久不一致**，直到磁盘上的文件再次变动（`lastModified` 再变一次）才会有下一次机会。

现实后果（今天就存在，不用等 Task 15/16）：「导出 HTML」「导出 Markdown」「打印」读的都是
store 里的 `document.content`，用户在编辑态改了东西再去导出，导出的是**改之前**的内容。
严格说这不是本轮引入的（Task 13 第 1 轮就把 `onChange` 只接进 `draftRef`），但本轮的护栏
让这个背离变得更持久、更无声。注释只说了「Task 16 应当把这个分支换成它给出的决策」，
没有说「退出编辑态之后两边就一直对不上了」。**建议把这一句补进注释并写进 progress 的已知风险。**

### 3.2 `defaultMode` 接线 —— 逻辑对，但降级路径**不够诚实**

对的部分：`useApplyDefaultMode` 这条路没有用户手势，因此不申请写权限、`writable` 保持
false，判断正确；`appliedEpochRef` 按 `openEpoch` 记账，用户退出后同一次打开不会被再拽回去；
挂在 `ReaderPage`（唯一实例）而不是并进 `useEditMode`，理由（`useToolbarActions` 同时被
工具栏和 `useGlobalHotkeys` 使用，会弹两次提示）成立。

不够诚实的两点：

1. **提示条会自动消失。** `Toast.tsx:27` 是 `setTimeout(dismissNotice, DURATION_MS[tone])`。
   几秒之后，界面上**再没有任何地方**能看出这份文档没有写权限——工具栏按钮显示「退出编辑」，
   与拿到写权限时一模一样；`writable` 要等 Task 17 的 StatusBar 才有出口。
   用户能看出自己没有写权限的时间窗口只有那几秒。
2. **提示条承诺了一个当前不存在的机制。** 文案是「写入权限要等第一次保存时才能申请」，
   而全仓 grep **没有任何 `mod+s` 绑定**（`useToolbarActions.ts` 里只有 `mod+shift+o`、
   `mod+shift+e` 等）。⌘S 要到 Task 15 才有。今天按 ⌘S 什么也不会发生，
   提示条却把它说成用户的下一步。

判定：**Important**。不阻断（本轮总体是把死设置接活了，方向正确），但「如实说明」这条
只在进入的那一瞬成立。

### 3.3 Tab 缩进 —— 绑对了，无障碍代价真实存在，逃生口已在但没人说

- **绑定正确**：`defaultKeymap` 确实不绑 Tab，全 `@codemirror/commands` 里 Tab 只出现在
  `indentWithTab` 一处（dist/index.js:1824 `const indentWithTab = { key: "Tab", … }`）。
  注释「`defaultKeymap` 有意不绑它」**属实**。
- **它确实会吃掉 Tab 的无障碍导航**——这是 CodeMirror 官方警告过的已知代价，本轮只在
  编辑态绑（`readOnly ? [] : keymap.of([indentWithTab])`），阅读态不受影响。
- **但键盘用户不会被困住**：`defaultKeymap` 自带官方逃生口
  `{ key: "Ctrl-m", mac: "Shift-Alt-m", run: toggleTabFocusMode }`（commands dist:1816），
  本项目用的就是 `defaultKeymap`，所以这个逃生口**已经在了**。

判定：**Minor**。代码没问题，问题在注释：它只说了阅读态不受影响（`阅读态按 Tab 仍然是
「跳到下一个可聚焦元素」，键盘用户不会被卡在正文里出不去`），**回避了编辑态才是真正付代价的
那一档**，也没提已经存在的 `Ctrl-m` / `Shift-Alt-m`。界面上同样没有任何提示。
建议注释改成「编辑态吃掉 Tab 是已知代价，逃生口是 defaultKeymap 自带的 Ctrl-m
（mac Shift-Alt-m）」。

### 3.4 进入编辑态不自动聚焦 —— 理由成立，现在这个行为可以接受

- **理由仍然成立**：进入编辑态不会移动选区，它停在文档位置 0。用户滚到中部按 ⌘E 后若自动
  聚焦，敲下的字确实会落到视口外的第一行——这正是本轮修掉的那个缺陷的另一个入口。
- **实测现状**：进编辑态后 `focused === false`，`activeElement` 是那个工具栏按钮
  （`class="inline-flex h-8 w-8 shrink-0 items…"`）。此时按键落到按钮/body 上，**什么都不会发生**，
  是安全的失败，不会写坏文档。
- **Critical 修好之后这个行为可以接受**：用户现在点一下正文就进去了，而且点哪块进哪块。

残留（本轮未复测，沿用上一轮结论）：**纯键盘用户仍然没有入口**——焦点在工具栏按钮上时按
方向键不会进入正文。要闭合得先把选区放到视口里的那一块再聚焦，正是注释里说的
「值得单独做、单独实测」。列为遗留 Important。

### 6.1 这条为什么是错的

`@codemirror/view` 6.43.11 的 `findWidget`（dist ≈2556-2578）：

```js
if (!this.reused.has(tile) && (pass == 0 ? tile.widget.compare(widget) : …)) {
    …
    if (tile.widget == widget && tile.length == length && …) {
        this.reused.set(tile, 1 /* Reused.Full */);
        return tile;                                   // 同一个实例才整块复用
    } else {
        this.reused.set(tile, 2 /* Reused.DOM */);
        return new WidgetTile(tile.dom, length, widget, …);  // 复用 DOM，换上**新** widget
    }
}
```

`compare()` 为真但实例不同时，CodeMirror **复用的是 DOM，采纳的是新 widget 实例**。
所以「eq 为真就继续用旧实例」这句话不成立，`ignoreEvent` 会在新实例（编辑态那套判据）上被调。

**dist 实测坐实了这一点**：把 `eq()` 改回只比 key，点段落的行为与原状**一模一样**，
老毛病并没有回来（第四节第三行）。

### 6.2 这条要不要改

`eq()` 里加 `viewEditable` 比较**本身无害**，它是一道更保守的防线（强制切换读写状态时
换新 widget），代价只是模式切换那一下多建一批 widget。我**不主张删掉它**。

要改的是两处**说法**：

- `live-preview.ts` 里 `eq()` 上方那段注释；
- **提交信息里也写了同一条**（「widget 的 eq 同时比较读写状态，否则切到编辑态后沿用阅读态的
  旧实例」）——与 Task 8d 那次「错误归因进了 commit message」如出一辙。

这是本项目**第四次**栽在「注释里的机制归因没查证」上。更值得注意的是：本轮有一条**新增用例**
（「切换读写状态的同一个块不算同一个 widget」）把这条错误归因**固化**了下来——它断言的
`eq() === false` 是真的，但它旁边的注释说「否则……又回到光标不动的老毛病」是假的。
下一个人读这条用例，会以为删掉它就会复活 Critical。
